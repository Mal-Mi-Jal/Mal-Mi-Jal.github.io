Ramen Vision Bot

Sep 2026 · personal

Classifies the style of ramen from a photo and explains the answer with sources, running entirely on one 8 GB GPU. A 7B vision model alone kept inventing styles, so I split the task: the VLM only describes what it sees, and retrieval over a curated knowledge base makes the call.

  • On 25 held-out photos never used for tuning: VLM alone 28% → full pipeline 60%.
  • Embeddings ignored negation ("no broth"), so I moved to hybrid retrieval (metadata filter + vector search); retrieval recall 61% → 91%.
  • Answers and source links are assembled by code from the documents, not written by the LLM, so every sentence is traceable.
  • Added a separate "is this a noodle dish?" gate after a non-ramen photo was classified as ramen. On 30 unseen photos: 14/14 other foods rejected, no real ramen rejected; noodle-less soup bowls still pass (2/18 false accepts, documented as a limit).
  • 12 experiments written up with before/after numbers, failures, and what was reverted.

Python · Ollama (qwen2.5vl:7b, 4-bit) · bge-m3 · Chroma · FastAPI

AI Research Agent

Sep 2026 · personal

A LangGraph agent that researches a topic and writes a report citing original sources (search → relevance check → outline → evidence retrieval → writing), served three ways: REST API, MCP server, and a daily n8n workflow.

  • Found a semantic-cache bug: an English-only embedding scored two different Korean questions at 0.928 and returned the wrong cached report. A multilingual model separated them (0.572); picked the 0.92 threshold by measuring 11 question pairs.
  • MMR retrieval raised cited sources per section from 13 → 16; the source list is attached by code to prevent invented citations.
  • Guarded the MCP file tool against path traversal (../).
  • Deployed in Docker on a 512 MB free instance by switching heavy modules off with an environment flag (≈124 MB vs ≈1.5 GB measured).

Python · LangGraph · Claude · Tavily · Chroma · MCP · n8n · Docker · Render

RamenLog

Jun – Sep 2026 · personal, backend and frontend

A ramen review service where you can only review a shop you actually visited: the app verifies the visit by GPS radius and time spent inside it.

  • Visit verification with the haversine distance; radius (50 m) and stay time (20 min) are external config, and a @Scheduled job completes verifications.
  • Kakao Local API search filtered by exact category match so only ramen shops come back; results are stored so nearby search needs no external call.
  • JWT access / refresh tokens with Spring Security, and a global exception handler.
  • JUnit 5 + Mockito boundary tests at ~40 m / ~60 m caught a missing-config bug the original 0 m test missed.
  • Multi-stage Docker build deployed to Railway; secrets in environment variables.

Kotlin · Spring Boot · JPA · Spring Security · PostgreSQL · JWT · JavaScript · Docker · Railway · Vercel
